# APS - Rendering Task Processing Service

**Калашян Артур**, гр. **5130904/40102**, вариант **24**.

Моделируется центр обработки заданий рендеринга: рабочие станции и сервисы отправляют задания, они ожидают в ограниченном буфере и обрабатываются вычислительными узлами. При переполнении возможен отказ заявки.

## Вариант СМО

`ИБ ИЗ2 ПЗ1 Д1ОЗ3 Д1ОО2 Д2П2 Д2Б5 ОР1 ОД3`

| Код | Правило |
|---|---|
| ИБ, ИЗ2 | Бесконечные источники, равномерные интервалы генерации |
| ПЗ1 | Экспоненциальное время обслуживания |
| Д1ОЗ3 | Первая свободная ячейка буфера без сдвига |
| Д1ОО2 | Отказ по приоритету номера источника |
| Д2П2 | Выбор свободного прибора по кольцу |
| Д2Б5 | Приоритетные пакеты заявок одного источника |
| ОР1, ОД3 | Сводная статистика, пошаговая динамика |

При освобождении прибора или первом запуске обработки фиксируется пакет из ожидающих заявок выбранного источника. Он не пополняется новыми заявками; пока пакет не завершён, приборы работают только с ним.

## Приложение

В пошаговом режиме показаны схема СМО, календарь и журнал. В итогах есть выгрузки CSV и JSON. Во вкладке «Эксперименты» можно изменить размеры четырёх конфигураций и сравнить их.

Событийная модель находится в `backend/app/model/`, API — в `backend/app/main.py`, интерфейс — в `frontend/src/`.

Общий буфер позволяет источникам использовать любую свободную ячейку. Зонный буфер подходит, когда нужны гарантированные квоты и защита от вытеснения заявками другого источника.
